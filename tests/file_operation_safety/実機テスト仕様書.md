# ファイル操作の安全性 実機テスト仕様書

## 目的と状況

コピー・切り取りによる移動・上書き・ゴミ箱移動の確認画面、異常時の結果、データ保持をXubuntu上で確認する。自動テストの成功はGUI、実際の権限、ディスク容量、異なるファイルシステム上の動作を保証しない。

**既知の未解決事項:** 上書きの最終確認後から置換までの間に、別プロセスが上書き先を更新すると、その更新が失われる競合を一時ディレクトリで再現した。自動テストでは確認時点までの変更検知を検証しており、この隙間の安全性は保証されない。切り取りの上書きにも同種の確認後の競合がある。重要なファイルを使って試さない。

## 準備

1. 普段使うファイルや既存フォルダを使わず、ホーム内に今回専用の空フォルダを作る。以下は `~/dpane-safety-test` と呼ぶ。既存の同名フォルダがある場合は別名にする。
2. その中に `source` と `destination` を作り、Dpaneの別ペインで開く。テストごとにファイルを作り直す。例えば `source/item.txt` に `SOURCE`、`destination/item.txt` に `DESTINATION`、それぞれ別の内容を入れる。内容はテキストエディター等で確認する。
3. 実施日時、Dpaneの版、環境、各項目の結果（成功 / 失敗 / 未実施）、実際の内容と表示メッセージを記録する。失敗時は操作を止め、テスト用データを保存して結果を記録する。
4. ゴミ箱のテストでは専用のテストファイルだけを対象にする。既存のゴミ箱の中身は削除しない。確認後の片付けは自分で作成したテストデータに限る。

## テスト項目

| ID | 操作・条件 | 期待結果 |
| --- | --- | --- |
| M1 | 同名の通常ファイルをコピーして貼り付け、確認画面でキャンセル | 両方の内容が元のまま。追加ファイルなし。 |
| M2 | 同条件で「連番を付ける」 | 元と既存ファイルが残り、`item (1).txt` に `SOURCE` が入る。番号が既存なら次の空き番号になる。 |
| M3 | 同条件で「上書き」 | コピー元は `SOURCE` のまま、移動先だけが `SOURCE` になる。確認画面に既存ファイルを置換する旨がある。 |
| M4 | 同名ファイルを切り取り後に貼り付け、キャンセルし、続けて連番で貼り付け | キャンセル時は両方維持。再試行時は元が移動し、既存の `DESTINATION` は残る。 |
| M5 | 同名ファイルを切り取り後、「上書き」を選ぶ（同一ファイルシステム） | 確認後に元がなくなり、移動先が `SOURCE` になる。 |
| M6 | 同名のフォルダ同士、またはシンボリックリンクを含む衝突 | 上書き・結合を選べず、キャンセルでは両方の内容とリンク先が維持される。 |
| M7 | コピー元のフォルダ自身、またはその中のフォルダへコピー / 切り取りで貼り付け | 拒否され、元フォルダとその中身が変化しない。 |
| M8 | 複数の同名ファイルを選び、1件目の確認で上書き、2件目でキャンセル | 一件も操作を開始せず、元と先の全内容が維持される。 |
| M9 | いくつか選択して `Delete`、確認でキャンセル | 対象の件数・名前が確認でき、どの項目も移動・削除されない。 |
| M10 | 専用のファイルを `Delete` し、確認後にゴミ箱から復元 | 元の場所からゴミ箱へ移動し、復元後に内容が一致する。ゴミ箱全体は空にしない。 |
| M11 | 切り取りを予約後、別アプリで元ファイルを別のファイルに置き換えて貼り付け | 対象変更が表示され、新しい元ファイルと貼り付け先の既存データを維持する。 |
| M12 | 同名の上書き確認を開いた状態で、別アプリで移動先の内容を変更してから上書きを承認 | 変更を検知して中止し、変更後の移動先とコピー元を維持する。最終確認後の競合は本項目では証明できない。 |
| M13 | テスト専用の書き込み不可フォルダを貼り付け先にしてコピー・切り取り | エラーを表示し、元ファイルを維持する。実行ユーザーが書き込みできないことを事前確認し、終了後にテスト用フォルダの権限を戻す。 |
| M14 | 安全に用意できる場合のみ、別ファイルシステム上の専用先へ同名ファイルを切り取り、上書きを選ぶ | 移動は失敗し、元と既存の移動先の内容が維持される。事前に `df` 等で別ファイルシステムと確認する。 |
| M15 | コピー・切り取り後の移動先を右クリック / F2で同名に名前変更 | 上書きされず、両方の内容が維持される。 |
| M16 | 複数項目の切り取りで1件だけ失敗する条件を安全に作れた場合、成功後に再度貼り付ける | 成功分は移動先にあり、失敗分は元に残る。予約には失敗分だけが残り、再試行対象となる。条件を作れなければ未実施とする。 |

## 自動テスト

リポジトリのルートから実行する。

```sh
/usr/bin/python3 -m unittest discover -s tests
node tests/test_path_completion_ui.cjs ui/app.js
```

`tests/file_operation_safety/` では、一時ディレクトリと障害注入を使って、部分書き込み、上書き中の変更検知、異なるファイルシステムのエラー、連番の競合、ゴミ箱失敗、複数選択時のキャンセルと部分失敗を検証する。ディスク満杯や権限拒否は一部を模擬しており、実環境全般を網羅しない。
