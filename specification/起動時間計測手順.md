# 開発用 起動時間計測手順

起動中のdpaneを終了してから、リポジトリ内の端末で次を実行すると、各段階のT0からの経過時間が標準エラー出力に表示されます。

```bash
DPANE_STARTUP_TIMING=1 ./dpane
```

- T0: Pythonエントリーポイント到達（Pythonプロセス生成自体は含まない）
- T1: Pythonモジュールのimport完了
- T2: GTKアプリケーションのstartup完了
- T3: WebView生成完了
- T4: WebKitのHTML読み込み完了イベント
- T5: 初期ペインの一覧取得終了（取得エラーも終了として数える）
- T6: 初期ペインへの結果反映後、2回の描画フレーム通知を受けた時点

T4〜T6は非同期イベントのため番号順とは限りません。T6は描画完了の近似で、実際に画面へ表示されたことや操作可能な時点を厳密に保証するものではありません。既にdpaneが起動していると既存プロセスへの通知のみになり、全地点を計測できません。

通常のCSS・JavaScript参照とインライン化の比較は、次の2種類をdpaneを閉じてから順に起動します。両方とも `load_uri()` を使い、DOMContentLoaded、window.onload、T6だけを表示します。

```bash
# A: 通常の外部CSS・JavaScript
DPANE_STARTUP_TIMING=1 DPANE_STARTUP_COMPARE=1 ./dpane

# B: 同じ内容をHTMLに埋め込む
DPANE_STARTUP_TIMING=1 DPANE_STARTUP_COMPARE=1 DPANE_STARTUP_INLINE=1 ./dpane
```

Bは現在のHTML・CSS・JavaScriptから一時HTMLを起動時に作成し、終了時に破棄します。T6には一時ファイルの作成時間も含まれ、読み込み元のディレクトリも異なります。DOMContentLoaded・window.onloadの `JS開始から` の差はJavaScript内の同じ時計で比較できます。

同じ計測ログには、WebKitの読み込み開始・確定・終了、初期ペインごとの一覧取得開始・終了・件数・所要時間、JavaScriptの初期レイアウト構築と一覧反映の所要時間も表示します。`起動詳細 +... ms` はPythonが記録・受信した時刻、`JS開始から... ms` はJavaScriptの経過時間であり、別々の時計として扱います。フォルダのパスや項目名は出力しません。

一覧通知の遅れを調べるため、初期ペインごとの `run_javascript` 要求・完了通知と要求からの所要時間、JavaScript側の一覧受信開始時刻と `document.readyState`、`DOMContentLoaded`・`window.onload` の発生時刻も記録します。JavaScriptのイベントの前後関係は `JS開始から... ms` で比較し、Python側の要求・完了通知は `起動詳細 +... ms` で比較してください。JavaScriptからPythonへの通知や完了コールバックにも遅延が含まれます。

さらに `window.onload` 後、WebKitのPerformance APIで取得できるリソースの開始・応答終了・所要時間と、DOMContentLoaded・loadのイベント開始・終了時刻を出力します。時刻はJavaScript開始が0msで、それ以前はマイナスです。CSS・JavaScript以外のリソース名は `other` とし、パスは出力しません。APIが値を提供しない場合は `取得不可` と表示します。この情報だけでWebKit内部の初期化時間や画面描画時間を特定できるとは限りません。

通常画面と最小HTMLの読み込みを比較する場合は、dpaneを終了した状態から次の2種類を交互に数回起動し、各回の `T4 − T3` を比較します。両方とも `load_uri()` を使用します。

```bash
# A: 通常画面
DPANE_STARTUP_TIMING=1 ./dpane

# B: 計測用の最小HTML
DPANE_STARTUP_TIMING=1 DPANE_STARTUP_MINIMAL=1 ./dpane
```

各回のウィンドウは次の起動前に閉じます。Bにはファイル一覧と通常のUIがないため、T5・T6は出力されません。比較にはWebKitの起動、ファイル読み込み、通常画面の処理などが重なるため、この結果だけで個々の原因を断定することはできません。`DPANE_STARTUP_MINIMAL` は計測を有効にした場合のみ作用し、通常起動には影響しません。

初期ペインの一覧を読み込み完了後に一括送信する実験は、次のコマンドで行います。通常の計測と交互に複数回起動し、T4・T5・T6や体感を比較してください。

```bash
# 通常の取得ごとの送信
DPANE_STARTUP_TIMING=1 ./dpane

# 初期ペインを読み込み完了後に一括送信
DPANE_STARTUP_TIMING=1 DPANE_STARTUP_BATCH=1 ./dpane
```

一括送信は計測時の通常HTMLだけに適用し、通常起動や最小HTMLには影響しません。実験中は全ペインの取得が終わるまで結果を表示しないため、遅いフォルダがある場合はほかのペインの表示も遅れます。

初期一覧だけを応答付きメッセージで受け取る比較は次のコマンドです。初期ペインの後のフォルダ移動・更新は従来の通信を使用します。`DPANE_STARTUP_REPLY` は計測中の通常HTMLに限り有効で、`DPANE_STARTUP_BATCH` と両方指定した場合は応答付きメッセージが優先されます。

```bash
DPANE_STARTUP_TIMING=1 DPANE_STARTUP_REPLY=1 ./dpane
```

通常方式と同じログのDOMContentLoaded・window.onload・一覧受信時刻、およびT6を比較します。応答付き方式では初期一覧に `run_javascript` を使わないため、その要求・完了ログは出ません。
