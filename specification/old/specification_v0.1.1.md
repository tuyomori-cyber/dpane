# dir-group-webUI 仕様書 v0.1.1

- 作成日: 2026-11-04
- 状態: MVP基本操作の実機確認済み／ロードマップ2（ペイン管理）の仕様検討
- 対象: Xubuntu 24.04 / Xfce。Web技術によるGUIを利用。
- 位置づけ: dir-group の WebUI方式。Native方式とは独立して試作する。
- 変更元: `specification_v0.1.0.md`。ペインの動的な追加・削除をロードマップ2の対象として具体化した。

## 1. 背景・目的

キーボードから素早く起動でき、複数のディレクトリを上下左右に柔軟に分割表示できる、軽快なファイル管理環境を作る。

本方式は **HTML/CSS/JavaScript による複数ペインのファイルマネージャーUI** と、Linux側の既存機能を使うローカルバックエンドを組み合わせる。複数ペインは単一アプリウィンドウ内で管理し、X11上の複数ウィンドウを同期させない。

v0.1.0のMVP基盤、フォーカス表示、キーボードによる閲覧・移動・更新、既定アプリによるファイル起動は実装済みで、基本操作は実機確認済みである。本版では、固定の2・3ペインレイアウトを動的なペイン追加・削除へ拡張する。

## 2. 基本原則

- UIを低コストで試行錯誤できることを重視する。
- 各ペインは独立したディレクトリ、選択状態、フォーカス対象を持つ。
- ファイルシステムへのアクセスはバックエンドに分離し、UIから任意のシェルコマンドを実行しない。
- GIOなどLinuxの既存機能を可能な範囲で利用し、ファイル操作ロジックの全面自作を避ける。
- Web UIであることを軽量性の根拠にせず、起動感と操作感は実機で判断する。
- 今回の追加・削除はUI状態だけを変更し、ファイルシステムを変更しない。

## 3. 現在の実装範囲

- Python + GTK3 + WebKitGTKの単独アプリウィンドウで動作する。
- WebKitGTKの限定メッセージハンドラを通じ、GIOで読み取り専用のディレクトリ一覧を取得する。外部公開HTTP APIは持たない。
- 2ペインの左右・上下表示、3ペイン表示、境界ドラッグ、各ペインの階層移動を実装済みである。
- クリック、`Ctrl+Tab`、`Ctrl+Shift+Tab`、`Alt+1`〜`Alt+3`でアクティブペインを移動できる。
- `↑` / `↓`、`Enter`、`Backspace`、`F5`による閲覧操作と、GIO経由の既定アプリ起動を実装済みである。

固定レイアウトの切替UIは、動的なペイン構成の実装時に追加・削除操作と重複しない形へ置き換える。固定レイアウトを互換機能として維持することは本版の必須要件ではない。

## 4. 今回の対象範囲

### 4.1 ペイン追加

アクティブペインを分割元として、新しいペインを追加する。

| 操作 | 結果 |
|---|---|
| 左右分割して追加 | 分割元の右側に新しいペインを追加する。 |
| 上下分割して追加 | 分割元の下側に新しいペインを追加する。 |

- 分割前の領域は、分割元と新規ペインで原則等分する。
- 新規ペインは分割元の表示ディレクトリを引き継ぎ、新たに一覧を取得する。
- 選択中の項目は引き継がない。既存ペインのディレクトリと選択状態は変更しない。
- 新規ペインには一意の内部IDを与え、追加後はそのペインをアクティブにする。
- 表示ペイン数が8の場合は追加を行わない。追加ボタンは無効にし、ショートカットも何もしない。エラー表示は必須としない。

### 4.2 ペイン削除

アクティブペインを閉じる。閉じる対象はUI上のペインだけであり、表示中のディレクトリおよびファイルへ変更を加えない。

- 削除後は、対象と同じ分割ノードの残存側（ペインまたは分割領域）を拡張し、空白領域を残さない。
- 他のペインのディレクトリと選択状態を初期化しない。
- 削除後のアクティブペインは、原則として削除対象に隣接していた残存ペインとする。残存側が分割領域の場合は、その中の表示順で先頭のペインを選ぶ。
- ペインが1つのときに閉じる操作を行った場合、アプリケーションを終了する。未保存のUI状態やファイル変更は扱わないため、今回は終了確認を表示しない。

この仕様ではアプリ実行中の最小表示ペイン数は1である。ただし最後のペインを閉じる操作の完了後は表示ペイン数0となり、直ちに終了する。

### 4.3 レイアウトとサイズ変更

- 左右・上下の分割は入れ子にでき、任意の表示ペインを分割元にできる。
- 追加・削除後も既存の境界ドラッグによるサイズ変更を維持する。
- 内部表現は分割ツリーを第一候補とする。葉をペイン、内部ノードを分割方向・比率・子ノードとして保持すれば、任意のペインの分割と、削除時の兄弟領域の昇格を局所的に処理できるためである。
- 代替として平坦なペイン一覧と都度のGrid計算があるが、上下左右を混在させた局所分割・削除の対応が複雑になるため採用しない。
- 厳密な最小ペインサイズは本版で保証しない。狭い領域は許容するが、レイアウト計算の異常でペインが操作不能になったり、アプリ全体の表示が破綻したりしてはならない。
- レイアウトの保存・復元、アクティブペインの一時拡大、ドラッグによる並べ替えは対象外とする。

### 4.4 フォーカスとキーボード操作

青いアクティブ枠、JavaScript上のアクティブペイン状態、DOMキーボードフォーカスは常に同じペインを指す。

| 操作 | ショートカット |
|---|---|
| 左右分割して追加 | `Ctrl+Shift+L` |
| 上下分割して追加 | `Ctrl+Shift+J` |
| アクティブペインを閉じる | `Ctrl+Shift+W` |
| 次の表示ペイン | `Ctrl+Tab` |
| 前の表示ペイン | `Ctrl+Shift+Tab` |
| 指定位置のペインへ移動 | `Alt+1`〜`Alt+3` |

- 既存のキーボード操作は維持する。
- `Ctrl+Tab` と `Ctrl+Shift+Tab` は、現在表示されている全ペインを表示順で循環する。
- `Alt+1`〜`Alt+3`は従来どおり先頭から3つの表示ペインへの直接移動とする。4〜8番目への直接移動は別途検討する。
- WebKitGTKまたはGTK側とショートカットが競合した場合は、独断で別キーへ変更せず報告する。

### 4.5 ツールバー

ツールバーには次の操作を置く。

- 左右分割して追加
- 上下分割して追加
- アクティブペインを閉じる

固定レイアウトの切替操作と同一機能のボタンは残さない。8ペイン時は2つの追加ボタンを無効化する。閉じるボタンは1ペイン時も有効とし、アプリ終了操作として扱う。

## 5. アーキテクチャと安全性

```text
Web UI (HTML / CSS / JavaScript)
  ├─ ペイン状態・分割ツリー・フォーカス管理
  ├─ 一覧表示・選択・階層移動
  └─ キーボード／境界ドラッグ操作
           │ 限定メッセージ
           ▼
Python + GTK3 / WebKitGTK
           │
           ▼
GIO（読み取り専用のディレクトリ列挙、既定アプリ起動）
```

- ペインごとにWebKitGTKインスタンスやPythonプロセスを作らない。
- 任意コマンド実行API、外部公開ポート、新しいフレームワークは追加しない。
- 既存のディレクトリ閲覧と既定アプリ起動を維持する。
- ファイルのコピー、移動、削除、名前変更、ゴミ箱操作は実装しない。

## 6. 受け入れ条件

- [ ] 1〜8ペインを動的に追加できる。
- [ ] 8ペインではボタン・ショートカットとも追加できず、既存レイアウトが変化しない。
- [ ] 左右・上下の分割を組み合わせられる。
- [ ] 追加したペインで独立してディレクトリ移動できる。
- [ ] ペインを閉じると残存領域が自然に拡張され、空白が残らない。
- [ ] 追加・削除後も境界ドラッグが機能する。
- [ ] 追加・削除後も青いアクティブ枠とキーボード操作対象が一致する。
- [ ] `Ctrl+Tab` / `Ctrl+Shift+Tab` で表示中の全ペインを循環できる。
- [ ] 既存の閲覧・既定アプリ起動が正常に機能する。
- [ ] 最後の1ペインを閉じるとアプリが終了する。
- [ ] 追加・削除を繰り返しても、ペイン数・表示・フォーカスが破綻しない。

## 7. 今回実装しない機能

- レイアウト保存・復元
- アクティブペインの一時拡大表示
- ペインのドラッグによる並べ替え、別ウィンドウ化、名前付け
- ペイン間のファイルドラッグ＆ドロップ
- ファイルのコピー・移動・削除・名前変更、ゴミ箱
- 8ペインを超える表示、複雑なレイアウトプリセット
- `Alt+4`〜`Alt+8`による直接フォーカス移動

## 8. 実装と確認の順序

1. ペイン状態を固定レイアウトから分割ツリーへ移行し、既存の2・3ペイン表示と境界ドラッグを保つ。
2. 左右・上下への追加、8ペイン上限、追加後のフォーカスを実装する。
3. 削除、兄弟領域の拡張、削除後のフォーカス、最後のペインでの終了を実装する。
4. ツールバーとショートカットを接続し、追加・削除の繰り返しを実機で確認する。

最優先は8ペインまで増やせること自体ではなく、追加・削除を繰り返しても自然に操作できることである。

## 9. 次の一歩

本仕様を正本として、ペイン追加・削除を実装する。実機確認で操作感を評価した後、表示パスのコピー、レイアウト永続化、または安全なファイル操作の優先順位を判断する。
