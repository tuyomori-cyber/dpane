# dir-group-webUI 仕様書 v0.1.2

- 作成日: 2026-11-04
- 対象: Xubuntu 24.04 / Xfce / X11、Python + GTK3 + WebKitGTK + GIO
- 位置づけ: [v0.1.1](specification_v0.1.1.md) を継承し、ファイルを開く・実行する操作を追加する。矛盾する場合は本版を優先する。

## 1. 目的と既存機能

一つのウィンドウに独立した複数のディレクトリを表示し、左右・上下の分割、境界ドラッグ、階層移動、キーボード操作を行う。v0.1.1のペイン管理、既定アプリで開く動作、安全上の制約を維持する。

## 2. ファイルを開く

- ファイルの `Enter`・ダブルクリック・右クリックメニューの「開く」は、GIOで既定アプリにファイルを渡す。ディレクトリは従来どおり移動する。
- 既定アプリが存在しない場合、GTK標準のアプリ選択部品を用いたダイアログを表示する。選択したアプリで対象ファイルを開き、関連付けは変更しない。GTK標準の `AppChooserDialog` 自体は選択時に最近使ったアプリの関連付けを記録するため、標準の `AppChooserWidget` を `Gtk.Dialog` に組み込む。
- 右クリックメニューの「別のアプリで開く」または `Ctrl+Shift+O` から、既定アプリの有無にかかわらず同じ選択ダイアログを表示できる。
- 対応アプリがない場合はその旨を表示する。ダイアログをキャンセルした場合は起動せず、元のペインにフォーカスを戻す。起動失敗はペインに表示する。
- 操作対象は選択中のローカル通常ファイルとする。アプリ選択はインストール済みアプリから行い、任意のコマンド文字列を受け付けない。システムの関連付けは変更しない。

## 3. 実行可能ファイルの起動

- 通常ファイルは既定では直接実行しない。右クリックメニューの「実行」または `Ctrl+Shift+E` で明示的に実行する。
- バックエンドで実在するローカル通常ファイルであることと実行権限を確認する。`.desktop` ランチャーは対象外とする。
- 実行前にファイルパスを示す確認ダイアログを表示し、承認時のみ実行する。キャンセル時は何も実行しない。
- 確認後もファイルと権限を再確認し、シェルを使わずファイルを直接起動する。引数は渡さず、作業ディレクトリは対象ファイルの親ディレクトリとする。
- 起動失敗は表示する。起動の受付と正常終了は区別し、実行中プロセスの管理・終了結果の監視は行わない。実行したプログラムはユーザー権限でファイル変更等を行い得る。
- 対話端末や標準入力が必要なプログラムの実行は対象外とする。スクリプトはOSが直接起動できる場合に限られ、インタープリターの指定・自動判定はしない。

## 4. 受け入れ条件

- [ ] 既定アプリが設定されたPDF・Markdown・画像を既存操作で開ける。
- [ ] アプリ指定で選んだアプリに対象ファイルが渡り、既定の関連付けが変化しない。
- [ ] 既定アプリがないファイルでは選択ダイアログが自動表示され、キャンセル後は元ペインにフォーカスが戻る。
- [ ] 対応アプリがない場合、または起動に失敗した場合は理由が表示される。
- [ ] 実行可能ファイルは確認画面を承認したときのみ、引数なし・シェルなしで起動する。キャンセル時は起動しない。
- [ ] 実行権限がないファイル、存在しないファイル、ディレクトリ、`.desktop` は直接実行できない。
- [ ] 右クリックとキーボードで各操作ができ、既存のペイン操作が維持される。

## 5. 今回実装しない機能

実行時の引数指定、ターミナルでの実行、ファイル関連付けの変更、起動後プロセスの管理、`.desktop` ランチャーの直接起動、コピー・移動・削除・名前変更、レイアウト保存・復元。
