# dir-group-webUI ペイン追加・削除 追加仕様 v0.1

## 1. 目的

既存のdir-group-webUIに、ペインの動的な追加・削除機能を実装する。

現在の2〜3ペイン固定表示を拡張し、ユーザーが必要な数のディレクトリを自由に並べられるようにする。

今回の実装範囲は、ペインの追加・削除と、それに伴うレイアウト・フォーカス管理に限定する。

## 2. 基本仕様

| 項目 | 仕様 |
|---|---|
| 最小ペイン数 | 0（アプリ終了） |
| 最大ペイン数 | 8 |
| 起動時のペイン数 | 現在の初期設定を維持 |
| ペイン追加 | アクティブペインを分割 |
| 分割方向 | 左右・上下 |
| ペイン削除 | アクティブペインを閉じる |
| 追加後のフォーカス | 新しいペイン |
| 削除後のフォーカス | 残存するペイン |
| 最後のペイン削除 | アプリ終了 |
| レイアウト保存 | 今回は対象外 |

## 3. ペイン追加

### 3.1 基本動作

アクティブペインを基準として、新しいペインを追加する。

追加方法は次の2種類とする。

- 左右分割：アクティブペインの右側に新しいペインを追加
- 上下分割：アクティブペインの下側に新しいペインを追加

既存ペインと新規ペインは、分割前の領域を原則として等分する。

追加後は新しいペインをアクティブにする。

### 3.2 新規ペインの初期状態

- 分割元ペインのディレクトリを引き継ぐ。
- ファイル一覧は新規に取得する。
- 選択中のファイルは引き継がない。
- 新規ペインには独立した内部IDを割り当てる。
- 既存ペインのディレクトリや選択状態は変更しない。

### 3.3 ペイン数の上限

ペイン数が8に達した場合、追加操作を受け付けない。

- 追加ボタンを無効化する。
- ショートカットからの追加も拒否する。
- 既存のペイン配置は変更しない。
- エラー表示は必須としない。

上限値は定数として管理し、複数箇所に数値を直接記述しない。

## 4. ペイン削除

### 4.1 基本動作

アクティブペインを削除する。

削除するのはUI上のペインのみであり、表示しているディレクトリやファイルには一切変更を加えない。

### 4.2 削除後のレイアウト

ペイン削除後は、空いた領域を残存ペインで埋める。

分割ツリーを採用する場合は、削除対象と同じ分割ノードに属する残存側のペインまたは分割領域を拡張する。

削除によって、他のペインのディレクトリや選択状態を初期化しない。

### 4.3 フォーカス

削除後は、原則として削除対象に隣接していたペインへフォーカスを移す。

フォーカス移動後は、青いアクティブ枠とキーボード操作対象を一致させる。

### 4.4 最後のペイン

ペイン数が1の状態で削除操作を行った場合、アプリケーションを終了する。

今回は読み取り中心のMVPであるため、終了確認ダイアログは設けない。

将来的にファイル操作の非同期処理を実装する場合は、終了処理を再検討する。

## 5. レイアウト管理

### 5.1 基本方針

ペイン数とレイアウトを分離して管理する。

既存の固定2ペイン・3ペイン表示を前提とした実装を、動的なペイン構成に対応させる。

内部データ構造はCodexが選択してよい。

ただし、以下を満たすこと。

- 左右・上下の分割を組み合わせられる。
- 任意の表示ペインを追加分割できる。
- 任意の表示ペインを削除できる。
- 削除後に空白領域が残らない。
- 既存の境界ドラッグによるサイズ変更が機能する。
- 既存ペインの状態が維持される。

分割ツリーは有力な実装候補だが、必須とはしない。

### 5.2 ペインの最小サイズ

今回の実装では、すべてのペインに厳密な最小表示領域を保証する必要はない。

ペイン数が増加すると、一部のペインが小さくなることを許容する。

ただし、レイアウト計算の異常によってペインが操作不能になったり、アプリ全体の表示が破綻したりしないようにする。

### 5.3 アクティブペインの表示領域

将来的には、アクティブペインの表示領域を優先的に確保する仕組みを検討する。

候補として、アクティブペインの一時拡大表示がある。

**今回は実装しない。**

## 6. UI操作

### 6.1 ペイン追加・削除ボタン

既存のツールバーに、以下の操作を追加する。

- 左右分割して追加
- 上下分割して追加
- アクティブペインを閉じる

既存のレイアウト切替UIとの関係は整理し、同じ機能を持つボタンが重複しないようにする。

### 6.2 キーボード操作

以下のショートカットを追加する。

| 操作 | ショートカット |
|---|---|
| 左右分割して追加 | `Ctrl+Shift+L` |
| 上下分割して追加 | `Ctrl+Shift+J` |
| アクティブペインを閉じる | `Ctrl+Shift+W` |

既存のショートカットは維持する。

- `Ctrl+Tab`：次の表示ペイン
- `Ctrl+Shift+Tab`：前の表示ペイン
- `Alt+1`〜`Alt+3`：指定位置のペインへ移動

`Alt+1`〜`Alt+3`は今回変更しない。4〜8ペインへの直接移動は別途検討する。

ショートカットがWebKitGTKまたはGTK側の操作と競合する場合は、勝手に別のキーへ変更せず報告する。

## 7. 安全性と制約

- ペインの追加・削除によってファイルシステムを変更しない。
- ファイル一覧取得は既存のGIOバックエンドを利用する。
- 任意コマンド実行APIを追加しない。
- ペインごとにWebKitGTKインスタンスを生成しない。
- ペイン追加のたびに独立したPythonプロセスを起動しない。
- 既存のファイル閲覧・起動機能を維持する。
- ペイン追加・削除のために新しいフレームワークを導入しない。

## 8. 実機確認項目

以下をMVPの受け入れ条件とする。

1. 1〜8ペインまで追加できる。
2. 8ペインの状態では追加できない。
3. 左右・上下分割を組み合わせられる。
4. 追加したペインで独立してディレクトリ移動できる。
5. ペインを削除すると残りの領域が自然に拡張される。
6. 追加・削除後も境界ドラッグが機能する。
7. 追加・削除後も青いアクティブ枠とキーボード操作対象が一致する。
8. `Ctrl+Tab` / `Ctrl+Shift+Tab` で表示中のペインを循環できる。
9. 既存のファイル閲覧・起動操作が正常に機能する。
10. 最後の1ペインを閉じるとアプリが終了する。
11. 追加・削除を繰り返しても、ペイン数や表示状態が破綻しない。

## 9. 今回実装しない機能

- アクティブペインの一時拡大表示
- ペインのドラッグによる並べ替え
- ペインの別ウィンドウ化
- レイアウトの保存・復元
- ペインの名前付け
- ペイン間のファイルドラッグ＆ドロップ
- ファイルのコピー・移動・削除・名前変更
- 8ペインを超える表示
- 複雑なレイアウトプリセット管理

## 10. 実装方針

既存MVPの動作を維持しながら、必要最小限の変更でペイン追加・削除を実現する。

レイアウト管理の内部構造はCodexの判断に任せるが、主要な設計変更を行った場合は、採用理由と代替案を作業レポートに残す。

まずは追加・削除とフォーカス管理を成立させ、実機で操作感を確認する。

**最優先は、8ペインまで増やせることではなく、追加・削除を繰り返しても自然に操作できることである。**
